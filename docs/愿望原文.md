# 愿望原文（一字未改）

我想做一个送给朋友的21岁生日 Web App，主要在手机上打开。它是一份可以互动的生日纪念作品，体验时长大概8～12分钟，重点是记录对方的生活，让对方感动，关系表达亲近、克制，不做表白或者刻意制造心动。
故事要站在收礼物的人的角度展开。内容围绕“你经历了什么、喜欢什么、怎样走到今天”，共同经历只是其中一部分。不能整篇都写成送礼的人在表达自己。
我想用一只小橘猫贯穿全程，带着对方走过七个场景。整段体验有一个共同的世界观：小猫正在整理一份给你的生日礼物，里面装着这一年的照片、地点、小事和祝福。你跟着它，把这些内容慢慢打开，最后一起到达生日房间。
小猫参考我提供的照片：金橘色毛、圆脸、大而黑亮的圆眼睛、奶白色嘴边和胸口，神态有点乖、有点好奇。需要重新设计成好看的2D动画角色。
小猫的头、身体、四肢和尾巴要有完整的连接关系。伸爪时，肩膀、前腿、爪子一起运动；走路时有步态；跳跃时有起跳、腾空、落地缓冲。需要准备等待、眨眼、回头、行走、探头、伸爪、推东西、跳跃、趴下这些动作。技术方案可以由制作方评估，但要能根据用户的操作切换动作。
整个故事按下面七幕发展：
第一幕，拆开一份会动的礼物。
打开网页先看到写着对方名字的纸包礼物。包装纸有纹理、折痕、封条和手写标签，里面偶尔轻轻动一下。
用户捏住封条的小角向下拉，纸随着手指撕开，裂口有不规则边缘和卷起的纸片。撕到一半松手，已经撕开的部分保留。
裂口足够大后，小猫从里面探头，前腿连着身体伸出来，停下来观察用户。用户碰一下它的爪子，它帮忙扒开剩下的纸，跳出来，碰落一张照片。照片滑向画面一侧，小猫追过去，再回头等用户。用户继续后，镜头跟随它进入下一幕。
第二幕，小猫照相馆。
镜头来到一张放着拍立得、照片和小物件的桌子。小猫踩到快门，照片吐出一截，用户亲手把它抽出来。
照片逐渐显影，出现真实照片、日期和一小段记录。照片可以翻面，背面有补充文字；照片中的某个小物件还可以点击，展开一条额外回忆。
这幕可以放两三张照片，有轻松、有趣的细节，让对方慢慢进入故事。最后一张照片背后夹着胶卷，小猫发现胶卷，把它拉到桌边，引出下一幕。
第三幕，把这一年的日子拉出来。
用户横向拖动胶卷，经过四到六个记忆节点，小猫沿着胶卷边缘前进。
每到一个节点，照片停稳，文字展开。内容可以包括开心的小事、认真做过的事、某次变化、一个难熬但走过来的阶段。读文字时，小猫停下来等待，用户操作后才继续。
其中一两个节点可以藏小互动，例如擦掉照片上的雾、打开一张折起来的便签，或者从几件小物品里找到与照片对应的那件。互动完成后多展开一点真实内容，不设分数，也不惩罚选错。
胶卷最后掉出一张车票，票面上的路线逐渐展开成地图。
第四幕，跟小猫重走几个地方。
地图要做成有插画场景的小世界，包含三到五个有意义的地点，比如学校、餐厅、回家的路、车站或旅行地点。
主线按顺序推进，每一站可以有少量自由探索：点路灯让灯亮起来，打开店门，移动一片挡着照片的树叶。小猫到站后会观察、坐下或碰一碰某个物件，引导用户发现记录。
点开地点后，可以看照片、短视频、对话或一段小故事。关闭内容后回到原来的地点，小猫和镜头的位置要接得上。已经走过的地点可以回看。
最后，小猫来到一家为生日亮灯的小店，推门进去，镜头穿过门进入下一幕。
第五幕，生日好运小卖部。
店内有老虎机、货架和一些与对方有关的小物件。用户可以先点货架上的两三件东西，看到小梗或简短留言。
老虎机作为主要互动：拉下摇杆后，窗口依次转动、减速，组合出一份生日愿望。愿望可以随机组合，但每一种都是祝福，不存在没中奖。
机器最后吐出一张卡片。小猫接住卡片，把它推给用户。这里是比较轻松的一幕，为后面的祝福留出节奏变化。
第六幕，刮开写给自己的话。
卡片上有一块可以刮开的涂层。小猫用爪子压住卡片一角，用户划过哪里，就露出哪里的文字。刮开一定面积后，剩余涂层自然散开，让完整内容能够舒服地阅读。
这里放整段作品里比较重要的话，具体写对方这一年的成长、努力和值得被肯定的地方。可以在后面展开朋友留言，留言像便签一样逐张打开，署名清楚。
读完后，用户翻到卡片背面，发现生日邀请。小猫带着邀请向一扇透着暖光的门走去。
第七幕，到达21岁的生日房间。
进入房间后，前面出现过的照片、车票、便签和小物件都摆在这里。用户能够认出，这些东西就是刚才一路打开的回忆。
用户可以点亮房间里的几盏灯，让照片墙逐渐显现，再点亮蛋糕上的“21”蜡烛。完成后出现生日祝福和最终寄语，小猫在旁边趴下，留一点安静的时间。
结束后提供一个回忆册入口，把照片、文字、地点和留言整理起来，方便重新浏览。希望还能保存一张生日纪念卡，作为这次体验的留念。
整体视觉希望是温暖、精致的2D绘本或者手作纪念册风格。纸张、胶片、地图、店铺和房间要属于同一个视觉体系，文字清楚，照片有足够空间。
场景切换要由小猫的动作和场景里的物件自然带出来。镜头可以跟随、推近、拉远、穿过门或者沿着胶卷移动。小猫要能和物件产生接触，动作有前后衔接。
声音希望有轻柔背景音乐，以及撕纸、快门、脚步、机器转动这些必要音效。由用户主动开启，并始终能够关闭。重要文字出现时，画面和声音都要给阅读留出空间。
操作以单指点击、拖动和滑动为主，避免精确操作。每个手势都需要简单提示，也要有按钮替代。支持返回、保存阅读进度和重新体验；动画不会擅自把用户带离还没读完的内容。
照片、文字和地点目前可以先用示例，但后期替换要方便，最好集中管理素材和内容。最终交付需要包括可运行的网页、源码、角色设计源文件和动画工程，并在 iPhone、安卓手机及微信内置浏览器里实际检查。
制作顺序希望是：先确认小猫形象和一段完整的伸爪动作，再精做第一幕，验证角色和转场效果，随后扩展到其余六幕。
